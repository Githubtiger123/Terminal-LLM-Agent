# 需求文档：Terminal LLM Agent（学习复现版）

> 本文档基于开源项目 MiniCode-go 的设计，定义我们即将从零实现的一套**教学型Terminal LLM Agent** 的需求。目标是理解「模型—Agent—工具—宿主」之间的协作方式，产出一个可运行的最小闭环，而非追求工业级完备。

## 1. 文档目的与范围

- **目的**：作为后续技术架构设计与编码实现的依据；同时作为团队学习「Coding Agent 核心机制」的路线对齐文件。
- **范围**：仅覆盖**单 Agent、单任务、单本地工作区**的核心能力。
- **明确排除**（列为后续扩展，不在本期）：Web UI、IDE 插件、多 Agent 协作、自动危险命令黑名单、环境变量/CLI 覆盖模型配置。

## 2. 系统定位

一个以 CLI 为主要交互入口的轻量级 Terminal LLM Agent：

- 运行在本地工作区，用户通过命令行与之多轮交互；
- Agent 通过大语言模型理解任务，并调用受控工具完成代码浏览、文件修改、命令执行与测试验证；

> 说明：本框架定名为 **Terminal LLM Agent**，是一个通用型的本地 LLM 工具调度框架；但其内置 `read`/`write`/`edit`/`bash` 工具使其天然具备 **coding 能力**——可读取与修改源代码、执行构建与测试命令、根据报错迭代修复。coding 是其首要但非唯一的应用场景。
- 核心闭环：**理解任务 → 检查代码 → 调用工具 → 修改代码 → 运行验证 → 根据结果继续修复**。

定位为「简单但完整的教学型 Terminal LLM Agent」：尽量减少框架依赖和非必要抽象，但保留 Terminal LLM Agent 的核心能力（模型调用、工具调用、Agent Loop、CLI 会话、Session 持久化、上下文压缩、项目记忆、执行前确认、流式输出、结果验证）。

## 3. 总体目标与约束

### 3.1 目标

- **G1 可运行**：从源码构建后在终端启动，能多轮对话并实际操作工作区。
- **G2 可控**：副作用工具执行前需用户确认，支持中断与超时。
- **G3 长程可用**：通过上下文压缩与项目记忆，支持较长任务不溢出模型窗口。
- **G4 可学习**：尽量减少框架依赖，保留 Agent 核心能力的清晰实现，便于逐日对照实现。

### 3.2 运行约束

- **宿主平台**：类 Unix（Linux / macOS / WSL）。不使用 Windows 专有 API（如进程组信号需 Unix 语义）。
- **语言**：Go（目标版本 1.26.x）。
- **模型服务**：兼容 OpenAI `/chat/completions` 接口（含 SSE 流式）。
- **配置**：TOML 文件，含 API Key；不读取 `.env` 或 `MINICODE_*` 环境变量，不提供 CLI flag 覆盖模型配置。
- **依赖**：尽量少；允许少量成熟库（Markdown 渲染、终端控制、UUID、TOML、OpenTelemetry）。

## 4. 角色与运行环境

- **用户**：在终端启动 Agent，输入自然语言任务，对副作用工具进行审批/拒绝，随时中断。
- **Agent**：在用户工作区内操作文件与执行命令，受审批与预算约束。
- **运行目录**：Agent 的工作区即启动命令时所在目录；配置、记忆、会话均相对该目录。

## 5. 功能需求

### 5.1 模型调用

- **FR-1.1** 支持向 OpenAI 兼容接口发起非流式与流式（SSE）请求。
- **FR-1.2** 流式响应在终端实时渲染，结束后展示完整 Markdown 回复。
- **FR-1.3** 固定 `max_tokens = 8192`，不提供输出上限配置项。
- **FR-1.4** 解析用量（`usage`）事件；模型不返回 `usage` 时明确显示不可用，部分响应标记 `partial`。

### 5.2 工具系统

- **FR-2.1** 内置四个工具：`read`、`write`、`edit`、`bash`。
- **FR-2.2** 工具以「声明（JSONSchema 参数）+ 执行函数」形式注册到注册表；声明发送给模型。
- **FR-2.3** 参数校验：必填字段缺失、未知字段、null 值、JSON 解码失败均报错并阻止请求。
- **FR-2.4** `read` 直接执行；`bash` / `write` / `edit` 执行前需用户审批。
- **FR-2.5** `bash` 在独立非交互 shell（`bash -c`）执行，合并 stdout/stderr 回传；单次输出上限 64 KiB，超出标记截断。
- **FR-2.6** `edit` 支持 `replace_all`，遵循「先读后改」与外部改动检测。
- **FR-2.7** 工具结果回传模型并进入会话历史，供后续轮次参考。

### 5.3 Agent Loop

- **FR-3.1** 接收用户输入 → 调用模型 → 解析 `tool_calls` → 执行工具 → 结果回传 → 循环。
- **FR-3.2** 单任务最多 500 轮工具调用；达上限后请求一次不带工具的最终总结。
- **FR-3.3** 带工具调用的中间文本不展示，仅模型不再调用工具时输出最终回复。

### 5.4 会话持久化

- **FR-4.1** 新会话生成 UUID，保存到 `.minicode/sessions/<id>.json`。
- **FR-4.2** 保存用户消息、模型回复、工具调用/结果、工作区、上一轮状态；系统 Prompt 在恢复时重建。
- **FR-4.3** 支持 `--session <id>` 跨进程恢复；严格拒绝非法/损坏 ID、版本不兼容、工作区不匹配、不完整工具消息。

### 5.5 上下文压缩

- **FR-5.1** 每次请求前检查上下文预算（固定 256K 窗口，余量 < 16K 时自动压缩）。
- **FR-5.2** 保留最近约 20K token 原文；更早内容用摘要替代（pi 摘要模板，首次 + 更新）。
- **FR-5.3** 支持 `/compact` 手动触发；模型报上下文超限时自动重试一次主请求。
- **FR-5.4** 严格消息校验：角色字段、完整参数 JSON、同批次调用 ID 唯一、调用与结果配对。

### 5.6 项目记忆

- **FR-6.1** 工作区根 `MiniCode.md` 常驻关键约定（≤ 64 KiB，原文预算 ≤ 4096 token）。
- **FR-6.2** 按需专题存 `.minicode/memory/*.md`，由模型按目录调用 `read` 加载。
- **FR-6.3** 每个用户轮次及 `/compact` 前重新读取；根目录记忆成功写入后整批工具完成再刷新。

### 5.7 终端 UI 与流式输出

- **FR-7.1** 当 stdin/stdout 均连接终端时，使用全屏会话界面，输入区固定底部，上方显示会话记录。
- **FR-7.2** 支持多行编辑、自动折行、`Shift+Enter`/`Ctrl+J` 插入换行、鼠标滚轮/`PageUp`/`PageDown` 滚动历史。
- **FR-7.3** 流式实时渲染 Markdown（标题/列表/加粗/代码块），后续增量按约 50ms 合并刷新；未闭合格式随新文本重排；窗口尺寸变化重排。
- **FR-7.4** 管道/文件输出保留纯 Markdown 原文，不渲染；渲染失败回退原文。

### 5.8 执行控制

- **FR-8.1** `Ctrl+C` / `SIGTERM` 触发 context 取消，终止模型请求与工具进程组（Unix 进程组）。
- **FR-8.2** 区分「用户中断 / 超时 / 普通失败」，给出不同提示，退出码不同。
- **FR-8.3** 默认超时 1 小时（`-timeout` 可配），覆盖模型请求、工具执行、摘要与总结。

### 5.9 可观测性

- **FR-9.1** 每轮展示统计：耗时、模型调用次数、工具调用次数、token（输入/输出/总）用量。
- **FR-9.2** 可选 Langfuse（OTLP/HTTP）追踪：用户输入、模型请求/响应、工具参数与结果、token 用量、耗时、错误。

### 5.10 配置管理

- **FR-10.1** 读取启动目录下 `config/config.toml`；缺失时兼容旧路径。
- **FR-10.2** 必填 `model.api_key` / `model.base_url` / `model.name`；可选 `langfuse`（两项同时留空关闭追踪）。
- **FR-10.3** 缺失或非法配置给出提示并退出，不回退到不可读/符号链接断裂的路径。

## 6. 非功能需求

- **NFR-1 可靠性**：断线/取消不执行半截工具调用；消息校验失败在本地拦截，不发送非法请求。
- **NFR-2 安全性**：无危险命令硬拦截；安全边界为逐次用户审批（`--yes` 可跳过，仅限可信场景）。
- **NFR-3 可维护性**：测试与源码分离（`test/` 黑盒，仅测导出 API）；全量 `go test -race` 通过；`go vet` 无错。
- **NFR-4 兼容性**：仅实现 OpenAI 兼容协议；其他 provider 作为后续适配扩展。

## 7. 明确的非目标（本期不做）

- 无 Web UI / IDE 插件 / 多 Agent（多 Agent 列入 Day 16 起）。
- 无自动危险命令黑名单或硬拦截。
- 无环境变量或 CLI flag 覆盖模型配置。
- 无思考强度（reasoning_effort）配置。

## 8. 验收标准（里程碑）

对照实现计划 Day 0–15 逐日验收：

1. 模型单次非流式与 SSE 流式调用可用，用量可解析；
2. 四个工具 + 注册表 + 审批 + 参数校验全部可用；
3. Agent Loop 正常循环，500 轮上限与最终总结正确；
4. 会话持久化与 `--session` 恢复正确，非法存档被拒；
5. 上下文压缩（自动/手动）与项目记忆加载/刷新正确；
6. 终端全屏 UI、流式渲染、中断/超时、统计与追踪可用；
7. （可选）真实模型语义验收：摘要保留目标/约束/进度，负例被正确拒绝。

## 9. 术语表

- **Agent Loop**：模型与工具之间的多轮循环驱动机制。
- **Provider**：模型调用抽象层，屏蔽具体协议差异。
- **Tool Registry**：工具声明与执行函数的注册表。
- **Session**：一次交互会话的持久化快照。
- **Compaction**：上下文压缩，用摘要替代早期历史以控制 token 用量。
- **Project Memory**：工作区内的常驻/按需项目知识（MiniCode.md 与 memory/）。
- **SSE**：Server-Sent Events，用于流式响应。
